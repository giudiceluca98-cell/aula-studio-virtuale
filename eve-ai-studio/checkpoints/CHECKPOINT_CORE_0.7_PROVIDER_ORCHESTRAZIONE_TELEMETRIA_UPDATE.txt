1. OBIETTIVO
======================================================================

Creare uno strato server indipendente che controlli come Eve seleziona ed
esegue i provider.

Il checkpoint deve impedire che:

- il client scelga liberamente un provider;
- il modello scelga da solo il proprio fallback;
- una chiamata superi i budget senza controllo;
- un provider esterno venga attivato accidentalmente;
- errori, prompt o risposte complete finiscano nella telemetria;
- chat e valutazioni condividano implicitamente le stesse regole.

======================================================================
7. TIMEOUT, RETRY E FALLBACK
======================================================================

Timeout:

- applicato con controllo asincrono;
- configurato per profilo;
- valutato per ogni tentativo.

Retry:

- numero massimo configurato;
- errori registrati solo tramite nome della classe;
- backoff configurabile;
- nessun testo completo dell’eccezione salvato.

Fallback:

- ordinato;
- usato solo quando il profilo contiene più target;
- indicato nella telemetria;
- non scelto dal modello.

Caso verificato:

1. modello primario lento;
2. TimeoutError;
3. passaggio al modello fallback;
4. risposta riuscita;
5. fallback_used=true;
6. due tentativi registrati.

======================================================================
8. TOKEN
======================================================================

Il Checkpoint 0.7 introduce una stima deterministica.

Metodo:

- serializzazione JSON canonica;
- lunghezza in caratteri;
- divisione approssimativa per quattro;
- arrotondamento per eccesso.

Vengono stimati:

- input_tokens;
- output_tokens;
- total_tokens.

La stima è adatta ai test e ai limiti preliminari.

Non è ancora il tokenizer ufficiale di un modello reale.

======================================================================
9. COSTI
======================================================================

Ogni modello può dichiarare:

- costo input per milione di token;
- costo output per milione di token.

Formula:

costo input =
input_tokens × input_cost_per_million_usd / 1.000.000

costo output =
output_tokens × output_cost_per_million_usd / 1.000.000

costo totale =
costo input + costo output

I modelli mock hanno costo zero.

I profili possono imporre:

- costo massimo per esecuzione;
- budget costi giornaliero.

======================================================================
11. PRIVACY DELLA TELEMETRIA
======================================================================

Non vengono salvati:

- messaggio utente;
- testo selezionato;
- risposta completa;
- contenuto della lezione;
- corpo completo dell’eccezione;
- chiavi API;
- credenziali;
- dati personali non necessari.

Vengono salvati hash SHA-256 della rappresentazione strutturata.

Gli hash servono a:

- distinguere esecuzioni;
- verificare stabilità;
- confrontare output;
- evitare la conservazione del testo completo.

- timeout;

- contesto troppo grande: HTTP 413;
- budget superato: HTTP 429;
- provider non disponibile: HTTP 502.
