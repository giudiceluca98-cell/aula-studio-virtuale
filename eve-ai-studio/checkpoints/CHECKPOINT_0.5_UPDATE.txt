5. SEVERITÀ
======================================================================

Livelli:

- critical;
- major;
- minor.

Un fallimento critical blocca sempre il gate.

Un fallimento non critico può essere tollerato soltanto quando:

- lo scenario non è obbligatorio;
- il punteggio ponderato resta sopra soglia;
- non esistono altri blocchi.

7. ESECUZIONI
======================================================================

Ogni run conserva:

- ID;
- versione prompt;
- data di avvio;
- data di completamento;
- stato;
- nota;
- snapshot delle versioni scenario;
- punteggio ponderato;
- scenari superati;
- scenari falliti;
- errori critici;
- fallimenti obbligatori;
- totale scenari.

Stati:

- running;
- passed;
- failed;
- error.

Un run non può essere completato due volte.

I risultati devono coprire esattamente lo snapshot.

Risultati mancanti o aggiuntivi bloccano il completamento.

======================================================================
8. RISULTATI PER CRITERIO
======================================================================

Ogni scenario può contenere più criteri.

Ogni criterio conserva:

- chiave;
- punteggio;
- outcome pass, fail o error;
- esito booleano;
- messaggio;
- sintesi dell’evidenza.

La sintesi dell’evidenza è limitata.

Non è necessario conservare intere conversazioni o contenuti sensibili.

Il punteggio scenario è la media dei criteri.

Il punteggio complessivo è ponderato usando il peso degli scenari.

======================================================================
9. GATE
======================================================================

Il gate è superato soltanto quando:

1. esiste un run completato;
2. è l’ultimo run della versione prompt;
3. la suite del run coincide con la suite attiva;
4. il run risulta passed;
5. gli errori critici sono zero;
6. i fallimenti obbligatori sono zero;
7. il punteggio raggiunge la soglia.

Il gate restituisce:

- eleggibilità;
- ultimo run;
- stato del run;
- punteggio;
- soglia;
- errori critici;
- fallimenti obbligatori;
- validità della suite;
- motivi del blocco.

======================================================================
10. COLLEGAMENTO AI PROMPT
======================================================================

Il PromptService dispone ora di un evaluation_gate.

Quando viene richiesto:

in_review -> publishable

il servizio:

1. legge il gate persistente;
2. blocca la transizione se il gate non è valido;
3. ignora un eventuale valore manuale true non supportato dai risultati;
4. registra il run che ha superato il gate;
5. permette la transizione soltanto con gate valido.

Il valore legacy review_tests_passed resta compatibile col contratto API,
ma non può aggirare il gate quando il modulo valutazioni è collegato.
