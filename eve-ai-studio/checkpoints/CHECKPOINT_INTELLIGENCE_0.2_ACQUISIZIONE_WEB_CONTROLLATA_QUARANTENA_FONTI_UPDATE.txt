======================================================================

Nel branch erano già presenti componenti tecnici sostanziali di INTELLIGENCE-0.2:

- app/core/config.py con i limiti server-side e il flag opt-in;
- app/intelligence/models.py con eventi e documento in quarantena;
- app/intelligence/web_acquisition.py con URL guard, DNS, IP pinning, TLS,
  redirect, robots.txt, MIME e limiti byte;
- app/intelligence/acquisition_storage.py con eventi e contenuti acquisiti;
- app/intelligence/service.py con orchestrazione, estrazione e SHA-256;
- app/intelligence/router.py con API dedicate;
- app/intelligence/__init__.py con gli export pubblici.

Questi moduli non vengono sostituiti. La soluzione riusa il codice esistente perché:

- riduce il rischio di regressioni;
- conserva i contratti già progettati;
- evita duplicazioni;
- mantiene separate le linee CORE e INTELLIGENCE;
- rispetta la regola secondo cui il modello non autorizza né esegue direttamente.

======================================================================
3. LACUNE REALI TROVATE
======================================================================

1. app/main.py costruiva ResearchCenterService senza SqliteAcquisitionStore e senza
   ControlledWebAcquirer. Di conseguenza le API esistevano ma il modulo risultava non
   disponibile nell'app principale.

2. .env.example non documentava le variabili già previste in EveSettings.

3. Il controllo robots.txt veniva eseguito soltanto sulla destinazione iniziale. Una
   catena di redirect poteva raggiungere un nuovo URL senza ricontrollare le regole di
   accesso applicabili a quella destinazione.

4. Non esisteva una suite specifica per le protezioni e i contratti di 0.2.

5. La preview canonica mostrava ancora INTELLIGENCE-0.1 e non rappresentava il nuovo
   flusso. Una prima proposta di sostituzione riduceva le funzioni precedenti; è stata
   scartata. Il modulo UI finale preserva creazione progetto, query e registrazione URL
   e aggiunge la pipeline di acquisizione senza eliminare nulla.

6. Mancavano UPDATE, VERIFICATION, CI_RESULT, CLOSURE e HANDOFF conformi alle regole
   correnti.

4.3 Robots su ogni destinazione della catena

File:
- eve-ai-studio/app/intelligence/web_acquisition.py

Intervento:
- la routine di follow riceve il parametro check_robots;
- prima di ogni richiesta al contenuto, compresa ogni destinazione ottenuta tramite
  redirect, viene verificato robots.txt quando la policy lo richiede;
- il recupero di robots.txt usa la stessa pipeline controllata ma disattiva il controllo
  ricorsivo per evitare cicli;
- un redirect verso un percorso o host non consentito viene bloccato prima del download
  del contenuto finale.

Motivo:
Il rispetto di robots.txt deve seguire l'URL realmente visitato, non soltanto il primo
URL inserito dall'utente.

4.4 Suite specifica

Nuovo file:
- eve-ai-studio/tests/test_intelligence_acquisition.py

Copertura prevista:
- flag disattivato per impostazione predefinita;
- schemi, credenziali e porte non consentite;
- IPv4 e IPv6 private, loopback, link-local e non globali;
- connessione fissata all'IP già validato;
- nessun proxy ereditato dall'ambiente;
- robots deny e robots unavailable in modalità fail-closed;
- robots rivalidato dopo redirect;
- limite redirect;
- blocco del downgrade HTTPS → HTTP;
- rivalidazione SSRF della destinazione redirect;
- rifiuto di compressione inattesa;
- allowlist MIME;
- limite byte;
- persistenza dell'evento;
- SHA-256;
- estrazione HTML senza script;
- stato quarantined obbligatorio;
- content_trust=untrusted_web_content;
- instructions_executable=false;
- idempotenza senza refresh;
- isolamento room_id;
- API con flag OFF e ON;
- nessuna approvazione o promozione automatica.
