4. VERSIONAMENTO IMMUTABILE
======================================================================

Ogni versione conserva:

- identificativo numerico;
- chiave stabile della configurazione;
- numero progressivo;
- data di creazione;
- stato;
- nome;
- prompt di sistema;
- modalità didattica;
- parametri JSON tipizzati;
- checksum;
- versione genitore;
- nota;
- indicazione della versione attiva;
- data di pubblicazione.

Una revisione non modifica la versione sorgente.

Ogni revisione genera una nuova versione con:

- nuovo ID;
- nuovo numero progressivo;
- stato draft;
- riferimento alla versione genitore.

======================================================================
5. STATI E TRANSIZIONI
======================================================================

Stati implementati:

- draft;
- in_review;
- publishable;
- published;
- archived.

Flusso principale:

draft -> in_review -> publishable -> published -> archived

Ritorni consentiti:

in_review -> draft
publishable -> draft

Transizioni vietate:

- draft -> published;
- draft -> publishable;
- in_review -> published;
- archived -> qualsiasi altro stato;
- passaggio allo stesso stato.

======================================================================
6. GATE DI PUBBLICAZIONE
======================================================================

Il passaggio da in_review a publishable richiede:

review_tests_passed = true

Senza questa condizione il backend restituisce un conflitto e non modifica lo
stato.

La pubblicazione è quindi controllata dal codice server e non dipende dalla
decisione del modello AI.

Quando una nuova versione viene pubblicata:

- diventa attiva;
- riceve la data di pubblicazione;
- la precedente versione attiva della stessa configurazione viene archiviata;
- lo storico resta disponibile.

======================================================================
10. ROLLBACK NON DISTRUTTIVO
======================================================================

Il rollback dei prompt non riattiva direttamente un vecchio record e non
cancella le versioni successive.

Il sistema:

1. legge la versione storica scelta;
2. copia contenuto, modalità e parametri;
3. crea una nuova versione progressiva;
4. assegna stato draft;
5. mantiene tutte le versioni esistenti.

La nuova bozza può quindi essere revisionata e pubblicata con lo stesso gate
delle altre configurazioni.

======================================================================
11. CONFIGURAZIONE INIZIALE
======================================================================

Al primo avvio, quando il database dei prompt è vuoto, viene creata la
configurazione:

configuration_key: eve-system
name: Eve Tutor Base
mode: adaptive_explanation

La configurazione iniziale viene fatta passare dal servizio attraverso:

- draft;
- in_review;
- publishable con test superati;
- published.

In questo modo anche il seed rispetta il workflow ufficiale.
